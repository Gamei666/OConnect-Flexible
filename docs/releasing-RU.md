# Сборка и подпись релизного APK

[English](releasing.md)

Настройте сборку под Windows по [инструкции](../README-RU.md). Используйте отдельный ключ подписи Android. Храните его и пароль в защищённом месте вне репозитория. Android использует подпись этого ключа для проверки обновлений уже установленных выпусков.

Задайте `OCONNECT_KEYSTORE_PASSWORD` в процессе PowerShell, получив значение из локального хранилища секретов. Если пароль самого ключа отличается от пароля хранилища, также задайте `OCONNECT_KEY_PASSWORD`. Выполните команду:

```powershell
.\build-android.ps1 -SdkPath C:\android -Keystore 'C:\path\to\release.p12' -KeyAlias oconnect-flexible
```

Скрипт собирает неподписанный APK, выравнивает его, подписывает, проверяет сертификат и вычисляет SHA-256. Подписывайте будущие выпуски тем же ключом. Храните резервную копию хранилища ключей и пароля в защищённом месте, чтобы выпускать обновления после переустановки системы.

Подготовленной сборке соответствует тег `v1.17.0-flexible.1`. Добавьте к одному выпуску GitHub подписанный APK, соответствующий архив исходников и их файлы SHA-256. В архив исходников входят нативные зависимости и сценарии сборки. Храните результаты сборки, ключи подписи, учётные данные, VPN-профили и реальные серверные конфигурации вне репозитория.

## Версии проекта

Тег Git должен соответствовать версии в APK, например `v0.1.0` для `versionName = "0.1.0"`. Если проект перейдёт на собственную нумерацию, указывайте версию оригинального OConnect в примечаниях к выпуску. Увеличивайте Android `versionCode` с каждым новым выпуском. Если меняете версию APK перед публикацией, соберите новый APK и архив исходников из того же коммита. [Версии Android-приложений](https://developer.android.com/studio/publish/versioning)
